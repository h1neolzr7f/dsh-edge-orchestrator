## Strengths

- Artifact receipt has a clear durability boundary. The handler consumes the entire bounded HTTP chunk before opening the staging file, truncates to the acknowledged offset, writes and syncs before advancing SQLite. Per-upload serialization, hash verification and the transaction containing both ready metadata and the event cover concurrent completion and the rename/commit crash window. Tests include a real interrupted 10 MiB transfer and Range verification.
- Process resumption verifies runner identity and retains diagnostics. The real test of shutdown during output transfer checks that the completed command executes once and that the uploaded bytes match. The buffered-event quarantine distinguishes protocol violations from storage errors, and scheduling assembles active load once per pass.
- Approval resolution, single-use code consumption and resulting credential creation have transactional boundaries. The pairing race/restart tests, static-token compatibility, TLS checks and hash-only Coordinator credential storage exercise concrete properties.
- The Cordis test builds the actual Go executables and spawns the Coordinator and two Workers. The Dart projection serializes changes, stages persistence before publication, and keeps per-card refresh barriers separate from the global cursor. The Flutter screen subtree requires permission, a same-task image reference, and an explicit host builder. The real demo records two overlapping test windows and verifies the downstream artifact.

## Critical

1. **A pinned Worker obtains artifact authority before approval, and retains output mutation authority after the task ends.** `apps/coordinator/artifacts_store.go:38`, `apps/coordinator/artifacts_store.go:45`, `apps/coordinator/artifacts.go:69`, `apps/coordinator/artifacts.go:129`. A controller-selected target is present in the immutable submitted envelope before dispatch. The download query explicitly includes waiting_approval. A Worker knowing the ID of an input or patch granted solely by a pending task can therefore fetch its bytes before the human approves disclosure. On the write side, target equality alone permits new upload sessions and ready events for queued, denied, cancelled and completed tasks. This can poison an eventual output name or add fabricated evidence to the final card. Grant live Worker transfer authority only when actually dispatched/accepted/running, and recheck mutation authority at publication if expensive hashing races terminalization. Preserve controller staging and the existing harmless same-owner lookup/repeat of an already completed upload, including the terminal retry in `tests/e2e_phase3_artifact_test.go:355`. Test waiting/read, denied/write, terminal/new-name and legitimate in-flight/ready-replay behavior through HTTP.

## Important

1. **Worker events can terminalize an undispatched or already rejected task.** `apps/coordinator/store.go:409`, `apps/coordinator/store.go:453`, `apps/coordinator/store.go:507`, `apps/coordinator/receipts.go:76`. On reconnect, a pinned Worker even receives reconciliation requests exposing IDs of waiting tasks. A new task.failed or task.cancelled event is legal in waiting_approval under the current negative status checks. Other invalid events trigger quarantine's broad UPDATE, which can turn queued/waiting/rejected into failed. For a pending approval this leaves a permanently pending approval with a terminal task. Limit worker-originated transitions and quarantine failure mutations to actual dispatched/accepted/running tasks, remove waiting tasks from worker reconciliation, preserve rejected terminal state and any existing decision. Keep exact historical duplicate ACKs valid after terminalization; quarantine an invalid new sequence and advance the Worker watermark without mutating an undispatched/terminal task. Verify that a following valid event for a different dispatched task still drains.

2. **An already-downloaded dirty patch fails restart preflight against the real range server.** `packages/artifact/client.go:241`, `apps/coordinator/artifacts.go:205`, `apps/edge-agent/workspace.go:269`. Patch download supplies no expected SHA and uses the server ETag. If an agent stops after downloading the full patch but before claiming the task (including while downloading another input), its retry asks for bytes at EOF. The Coordinator uses Go 1.24.2 http.ServeContent, whose default serveError strips ETag on the resulting 416. DownloadFile rejects the missing digest before reaching its local-file verification branch. Recover via a fresh authenticated successful response that supplies the expected digest, or store authenticated metadata durably alongside the partial download. Do not trust a locally computed checksum by itself. Test a complete retained patch with empty expectedSHA against the real handler and verify the recovered checkout applies it.

3. **Terminal workspace cleanup has no durable retry path.** `apps/edge-agent/agent.go:484`, `apps/edge-agent/agent.go:493`, `apps/edge-agent/store.go:239`, `apps/edge-agent/store.go:278`. A worker killed after terminal commit but before worktree removal retains the checkout permanently. The startup query excludes terminal tasks, and the recovered nonresumable-running branch calls finish without any cleanup at all. A transient cleanup failure has the same outcome. Record/recover pending cleanup or reconcile existing terminal task-owned checkouts on startup. Preserve all current live-runner, exit and log-drain safeguards. Test a persisted terminal task with its real registered worktree still present, and a previously running nonresumable task finalized during recovery. Both must retain diagnostics.

4. **Go HTTPS clients follow redirects that can disclose tokens or upload bytes.** `packages/artifact/client.go:47`, `packages/artifact/client.go:221`, `packages/edge-link/client.go:49`. Only the initial URL is validated. The production HTTP client has default redirect behavior. A proxy redirect to HTTP on the same hostname (including a different port), or a delegated subdomain, can receive the Authorization header. A 307/308 can forward an upload body even where Go drops Authorization. The public Go ClaimPairing wrapper can also forward its claim body, although the worker startup wrapper separately forbids redirects. Use an origin-confined redirect policy or reject redirects for credentialed fleet traffic. Treat a rejected redirect as a permanent semantic error so resumable operations do not loop indefinitely. Test two local servers with HTTPS-to-HTTP redirects and ensure neither credentials nor chunk contents reach the target. Inspection of the installed Go 1.24.2 net/http/client.go shouldCopyHeaderOnRedirect confirms that it compares host/domain and does not require the same scheme or port.

5. **The Cordis plan submission tool cannot replay the same idempotent input.** `integrations/dsh-cordis-plugin/src/index.mjs:19`, `integrations/dsh-cordis-plugin/src/index.mjs:156`, `apps/coordinator/store.go:159`. Even with an explicit plan_id and idempotency_key, two identical tool invocations generate different created_at timestamps. The tool schema disallows providing created_at. The Coordinator fingerprints the full envelope, so retry after a lost submit response or failed post-submit projection fetch returns IDEMPOTENCY_CONFLICT for valid unchanged work. I ran validatePlan twice with the same explicit IDs and identical arguments, verified different timestamps, and confirmed created_at is absent from the tool schema. Provide a stable request identity/envelope or recover an already-accepted matching plan on replay, retaining genuine semantic conflict detection. Cover the real tool with identical arguments after a simulated lost response.

6. **Fresh or rebased Flutter execution cards discard previously recorded logs.** `packages/edge-link-dart/lib/src/projection_store.dart:38`, `packages/edge-link-dart/lib/src/projection_store.dart:147`, `apps/edge-agent/process_store.go:160`. If a user opens a chat after command completion, or a cursor expiration triggers a fleet snapshot, the new projection has an empty logs map and the new barrier permanently skips every preceding log event. Even the stdout_summary/stderr_summary already in the completed process snapshot are ignored. The same happens to preceding running-task output when opening a second device. Hydrate a bounded authoritative log tail at the snapshot barrier (at minimum use the committed result summaries for completed commands), then append later events once. Add cold-open and expired-cursor tests with real pre-barrier output. The embedder's explicit approvals query covers pending decision IDs; it does not recover logs.

7. **An interrupted first claim permanently strands the selected device ID.** `apps/coordinator/pairings.go:89`, `apps/edge-agent/identity.go:131`, `apps/edge-agent/identity.go:142`. If the response is lost after the Coordinator commits, or the agent crashes before persisting the returned secret, the code is consumed, the server stores only the secret hash, and the Worker has no token. A fresh controller-issued code for the same ID then fails DEVICE_EXISTS. This breaks onboarding for that ID and tasks targeting it; restarting cannot recover it. Provide recoverable first enrollment without allowing a second redeemer to claim the code, for example by binding a durable per-attempt worker proof to the original claim and securely recovering the original grant, or an explicit controller-authorized recovery for that device. Regression: lose the successful response before local save, restart, recover the same ID, and prove an independent claimant still fails.

## Minor

1. **A failed complete hash check leaves no way to resend the correct bytes for that upload.** `apps/coordinator/artifacts_store.go:92`, `apps/coordinator/artifacts.go:135`. If a source changes between hashing and streaming, the final byte digest can differ despite the claimed expected SHA being correct for the user's intended file. Subsequent creates return confirmed_offset == size, and the offset check refuses a repair at zero. The task fails correctly, but even a controller retry with restored correct data cannot repair this session. Reset only an uncompleted, verified-bad session via an explicit restart or safe zero-offset reset, preserving ready artifact immutability. Test bad full contents followed by corrected contents with the original metadata.

2. **Failed Cordis saves can leave a partial file at the final path.** `integrations/dsh-cordis-plugin/src/index.mjs:125`. An ENOSPC/write failure closes the exclusive destination without removing it. After freeing space, an otherwise valid retry fails EEXIST and other readers can mistake a partial file for the artifact identified by its filename. Unlink only the handle's newly created destination on failure under the documented private-root assumption, or stage and publish without replacement. Preserve the existing no-overwrite rule.
